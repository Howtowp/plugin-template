# AGENTS.md — rules for coding agents (Cursor, Claude Code, Codex, …)

This repo is a **project** that contains one shippable WordPress plugin. Read this file first.

## Layout (project layout)

```
./                      repo root = project (never shipped as a whole)
├── plugin-template/    THE PLUGIN. Folder name = slug = zip root. Only this folder ships.
│   ├── plugin-template.php   main file: headers, constants, autoload, boot (no logic)
│   ├── src/                  PSR-4 `HowToWP\PluginTemplate\` (Core, Admin, Frontend, Rest, Abilities, AI,
│   │                         Integrations, Services, Repositories, Support)
│   ├── blocks/               block sources (block.json, render.php, view.js, index.js) → built into build/
│   ├── build/                generated by `npm run build` (git-ignored, built in CI)
│   ├── templates/            PHP templates, overridable by themes at {theme}/plugin-template/
│   ├── assets/src|dist       sources (not shipped) | compiled assets (shipped)
│   ├── languages/            .pot (+ fa_IR)   tests/ phpunit   readme.txt  LICENSE  uninstall.php
│   ├── bin/add-index.js      postbuild: puts index.php into build/ (bin/ never ships)
│   ├── index.php             "Silence is golden" in the plugin root and in every subfolder
│   └── composer.json package.json phpcs.xml.dist phpstan.neon.dist phpunit.xml.dist .distignore
├── docs/  data/  design/  research/  scripts/  dev/   project material, NEVER ships
├── .release.yml            release config (plugin_dir: plugin-template)
└── .github/workflows/      release.yml (calls howtowp/.github reusable workflow), plugin-check.yml
```

Simple layout (plugin at repo root) also exists for old product repos: same `.release.yml` without `plugin_dir`.
Details: <https://github.com/howtowp/.github/blob/main/docs/wordpress-release.md>.

## Security & standards (read first)

Full ruleset (Persian, authoritative): [`docs/security-rules.md`](docs/security-rules.md). Condensed Cursor rule: `.cursor/rules/wordpress.mdc`.
Golden rule: **Validate -> Sanitize (input) -> Prepare (query) -> Escape (output)**. Nonce **and** capability on every state change; real `permission_callback` on every REST route and ability. `exit` only for the `ABSPATH` / `WP_UNINSTALL_PLUGIN` guards and right after `wp_safe_redirect()`, `wp_send_json_*`, or a streamed download. Fix priority: security blockers, then release standards (enqueue, readme.txt/index.php, i18n), then quality (die/exit, error handling, line length, WPCS) — root-cause fixes everywhere the pattern repeats.

## Naming (after `scripts/init.sh` these are renamed; use the current names, never hard-code others)

- Slug / text domain / zip folder: `plugin-template`. Namespace: `HowToWP\PluginTemplate\`.
- Prefix **`htw_pt_`** for options, hooks, shortcodes, transients, tables, functions; **`HTW_PT_`** for constants; `htw-pt-` for CSS classes/handles.
- One class per file; file name = class name (`SettingsPage.php`). Every PHP file starts with `defined( 'ABSPATH' ) || exit;`.

## How to…

- **Add a module:** create `src/<Area>/<Name>.php` implementing `Core\Module` (`register()` only adds hooks, cheap, no queries), then list the class in `Plugin::module_classes()`.
- **Add an ability (AI/MCP):** in `src/Abilities/Abilities.php` add a `wp_register_ability( 'plugin-template/<name>', … )` inside `register_abilities()`: JSON-Schema `input_schema`/`output_schema`, a real `permission_callback` (never `__return_true` for private data), `meta.annotations`, `meta.show_in_rest`, `meta.mcp.public`. Category must be registered first on `wp_abilities_api_categories_init`. Put logic in a `Services/` class. Document in `docs/abilities.md`.
- **Add a block:** `plugin-template/blocks/<name>/` with `block.json` (`apiVersion 3`, `render`, `viewScriptModule` if interactive), `render.php`, `view.js` (Interactivity API), `index.js`. `npm run build` (inside `plugin-template/`) generates `build/` + `blocks-manifest.php`; `Frontend\Blocks` registers everything automatically.
- **Add a setting:** key in `SettingsRepository::defaults()`, field + sanitizing in `Admin\SettingsPage`, cleanup in `uninstall.php`.
- **Add a DB migration:** bump `Installer::SCHEMA_VERSION`, add `Upgrader::migrate_to_N()`.
- **Extensibility:** expose `do_action`/`apply_filters` with the `htw_pt_` prefix and list them in `docs/hooks.md`.

## Quality rules

- PHP ≥ 8.1, WordPress ≥ 6.8. Escape late, sanitize input, nonce + capability on every state change, `$wpdb->prepare()` always.
- WooCommerce: read orders with `wc_get_order()` (HPOS), never `get_post_meta()` on orders.
- AI features use the core AI Client (`wp_ai_client_prompt`), feature-detected; **never store or request API keys**.
- Checks (run inside `plugin-template/`): `composer install && composer lint && composer phpcs && composer phpstan && composer test`.
- Keep docs in `docs/` (project) and `readme.txt` (WordPress.org-style readme, shipped).

## Definition of Done

Same list as section 13 of `docs/security-rules.md`; all must be true before a commit/release:

- [ ] No `$_POST/$_GET/$_REQUEST/$_SERVER` without `wp_unslash` + sanitize; no output without context-correct escaping.
- [ ] Every query with variable input uses `$wpdb->prepare()` (or a WP API).
- [ ] Every PHP file has the `ABSPATH` guard (`uninstall.php`: `WP_UNINSTALL_PLUGIN`).
- [ ] Every state-changing action checks nonce **and** `current_user_can()`.
- [ ] No unauthorised `die`/`exit` (only the five allowed cases above); errors via `WP_Error`.
- [ ] All CSS/JS via `wp_enqueue_*`; data to JS via `wp_add_inline_script` / `wp_interactivity_state` (not `wp_localize_script`).
- [ ] Every REST route and Ability has a real `permission_callback` (write/delete never wide open).
- [ ] `readme.txt`, `uninstall.php` and `index.php` (silence) exist in the plugin root and every subfolder; `build/` gets its `index.php` from `npm run build` (postbuild).
- [ ] All strings i18n'd with text domain = slug; all globals prefixed; classes in `src/` with PSR-4 namespace.
- [ ] `composer phpcs` (0 errors, 0 warnings), `composer phpstan`, `composer test` green; no line over 120 characters; no PHP warnings/notices.
- [ ] No API key or secret in code (options/constants only); AI only via the core AI Client.
- [ ] `npm run build` works and Plugin Check is green in CI.
- [ ] Release: version, `readme.txt`, `CHANGELOG.md` updated; no secrets, zips, `.env`, `node_modules`, dev `vendor` or private data committed.

## Release rules

- SemVer. Work on `dev`, merge to `main`, tag `vX.Y.Z` on `main`. **The tag must equal the `Version:` header** in `plugin-template/plugin-template.php` (also update `HTW_PT_VERSION`, `readme.txt` Stable tag, `package.json`, `CHANGELOG.md`).
- Tag push → GitHub Actions builds `plugin-template-X.Y.Z.zip` (root folder `plugin-template/`) and attaches it to a Release. Manual run (`workflow_dispatch`) is a dry-run by default.
- There is **no** in-dashboard auto-updater. Customers download from howtowp.ir.
- Never create/move tags from automation, never force-push `main`.

## Never commit

Tokens, API keys, `.env*`, private keys, customer data, zip files, `node_modules/`, dev `vendor/`, `build/` output, large/private datasets (use `data/sample/` for small fixtures). `docs/`, `data/`, `design/`, `research/`, `scripts/`, `dev/` must never end up in the plugin folder or the zip.
